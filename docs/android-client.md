### 持续签名与打包

`scripts/initialize-signing.ps1 -JavaHome <JDK21目录>` 仅首次生成长期签名；再次运行验证原签名，不替换已有密钥。不完整的签名文件会使脚本停止，必须先恢复原文件。默认私有位置为工程 `work/private/android-signing/`，Windows ACL 限制为当前用户与 SYSTEM，Git 忽略该目录。密码只在受限私有文件与短时进程环境中使用，不打印、不进入 APK。

`scripts/build-pilot.ps1 -JavaHome <JDK21目录> -AndroidSdk <SDK目录> [-GradleCommand <Gradle路径>] [-Offline]` 要求源码已提交，构建 release、校验证书指纹，并在 `outputs/android/` 生成 APK 和对应版本验证 JSON。同名交付包若内容不同会拒绝替换，应递增版本。脚本恢复其使用的进程环境变量，签名备份保存在腾讯工程私有 `config/android-signing/`，不能放进 APK 公开归档。

0.1.0 使用开发调试签名；0.2.0 开始使用上述长期发布签名。Android 不允许跨签名覆盖安装，已安装 0.1.0 的设备需先确认没有未上传草稿，再卸载旧版并安装 0.2.0；之后的版本沿用同一签名并递增版本号。卸载会清除本机草稿与登录信息，已上传的服务器资料不随卸载删除。

## 能力边界与真机验收

自动切题的可靠坐标、真实手写识别质量、逐步诊断、分步辅导、独立变式和长期学情尚未通过真实样本验收。首轮后台可返回识别候选；没有可信区域时提示手动框选，不伪造自动框线。此次真实接口联调关闭了模型调用。

APK 编译成功不等于真机相机、Keystore、相机进程恢复或各种厂商 WebView 已通过验证。0.2.0 已具备生产移动接口和长期发布签名，但尚未连接真实手机/平板进行上述检查，应先由一个家庭试用完整流程，再扩大范围。

## APK 下载交付规则

用户于 2026-10-01 要求每次 APK 上传腾讯云并提供下载地址。每次用于交付的新包均按以下顺序处理：

## 开发与构建

客户端是独立 npm 项目，不修改服务器根 `package.json` 或锁文件。Node 24；Android 使用 Java 21、SDK 36 与项目 Gradle Wrapper。依赖由客户端 `package-lock.json` 固定。

```powershell
cd clients/android
npm ci --no-audit --no-fund
npm run dev
npm run build
npm run lint
npm test
npm run android:sync
cd android
.\gradlew.bat :app:assembleDebug
```

Vite 仅监听 `http://127.0.0.1:3178`。本机 Windows 排除端口包含 4178，故不用该端口。开发后端的 `FAMILY_MOBILE_ORIGINS` 需精确包含此来源和 Android 的 `https://localhost`，浏览器请求 `credentials: omit`；不要放宽网页 Cookie 路由的同源规则。

构建时可设置 `VITE_API_URL=https://自己的服务/family-learning/api/mobile/v1`，只放公开服务地址。未设置时，登录页提供初次服务地址配置。仅开发模式允许回环 HTTP；APK 和生产 Web 构建要求 HTTPS。不要在 APK 中使用 `server.url` 直接加载远程网页，也不要关闭证书验证。

手动执行 `assembleDebug` 生成 `android/app/build/outputs/apk/debug/app-debug.apk`，使用调试签名。家庭试用交付请执行上述 `scripts/build-pilot.ps1`，沿用长期发布签名，不能把签名私钥、密码、学习原件和测试账号提交 Git。

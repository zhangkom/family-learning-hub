### 持续签名与打包

`scripts/initialize-signing.ps1 -JavaHome <JDK21目录>` 仅首次生成长期签名；再次运行验证原签名，不替换已有密钥。不完整的签名文件会使脚本停止，必须先恢复原文件。默认私有位置为工程 `work/private/android-signing/`，Windows ACL 限制为当前用户与 SYSTEM，Git 忽略该目录。密码只在受限私有文件与短时进程环境中使用，不打印、不进入 APK。

`scripts/build-pilot.ps1 -JavaHome <JDK21目录> -AndroidSdk <SDK目录> [-GradleCommand <Gradle路径>] [-Offline]` 要求源码已提交，构建 release、校验证书指纹，并在 `outputs/android/` 生成 APK 和对应版本验证 JSON。同名交付包若内容不同会拒绝替换，应递增版本。脚本恢复其使用的进程环境变量，签名备份保存在腾讯工程私有 `config/android-signing/`，不能放进 APK 公开归档。

0.1.0 使用开发调试签名；0.2.0 开始使用上述长期发布签名。Android 不允许跨签名覆盖安装，已安装 0.1.0 的设备需先确认没有未上传草稿，再卸载旧版并安装 0.2.0；之后的版本沿用同一签名并递增版本号。卸载会清除本机草稿与登录信息，已上传的服务器资料不随卸载删除。

## 分工与集成

| 会话 | 负责范围 | 分支 |
| --- | --- | --- |
| 本会话 | `clients/android/`、孩子端交互、Android 工程、客户端验证与整体联调 | `codex/android-family-client` |
| 大小宝名校计划 | `server/`、`lib/`、现有 `app/`、家长网页、根工具链配置、后台数据与任务 | `codex/mobile-backend-v1` |

接口以另一分支的 `docs/mobile-api-v1.md` 为准，部署基础路径 `/family-learning/api/mobile/v1`。两个分支从 `58b3ee3` 开始，开发目录独立，避免共同修改文件。由本会话收口接口与联调；集成后统一发布，不让两个会话同时操作生产数据、迁移或部署。

项目规模适合两个会话分工。一个会话顺序实现更简单，但界面和后台需要交替等待；当前接口明确后，独立客户端与后台可以并行。无需再按页面拆出更多会话，否则会增加接口协调与合并成本。

## 已实现

- React + Vite 静态客户端与 Capacitor Android 工程，适配手机单栏、平板双栏；当前名称、图标均为开发期默认。
- 家庭登录、服务端会话校验与注销，学生列表、新增学生和本设备选择；浏览器 token 仅内存，原生使用 Android Keystore 加密存储插件。
- 拍照和相册入口，JPEG/PNG/WebP 上传；上传前照片保存在 IndexedDB，按服务地址、家庭、学生隔离，重试复用请求 ID。服务端首轮限单张 8 MiB。
- 扫描列表、任务状态、鉴权原图；切换学生后迟到的列表响应不能覆盖当前学生资料。
- 归一化矩形框选、移动和右下角缩放、补题、拆分区域成新题、合并题目、删除题目/框；支持父题及共用题干/配图引用。
- 逐步手写转写编辑，区分孩子、老师与作者不明，保留涂改、不确定项和原图区域关联。每题可分别核对。
- 校对草稿自动保存在本机，重新打开恢复；409 冲突阻止覆盖，保留、复制或在浏览器导出本机草稿后加载服务器版本。旧轮询结果不能覆盖正在编辑的内容。
- 原生相机恢复事件处理、禁止明文 HTTP 与混合内容、关闭应用自动备份。没有模型密钥进入客户端。

## APK 下载交付规则

用户于 2026-10-01 要求每次 APK 上传腾讯云并提供下载地址。每次用于交付的新包均按以下顺序处理：

1. 确认版本号、递增的 `versionCode`、对应源码提交及签名；记录 APK 大小和 SHA-256。
2. 上传腾讯云本项目专用下载目录，保留版本独立地址；经核验再更新最新 APK 入口。只发布 APK 和不含隐私的版本信息。
3. 用正常证书验证访问公网 HTTPS 地址，确认响应和下载文件哈希；检查当前网站仍可访问，下载入口没有公开内部归档。
4. 回复用户时直接给出下载链接、版本、大小、主要变化和验证状态。开发包须注明，真实模型或真机尚未验收时须明确说明。

私有归档和公开下载职责不同：`artifacts/android/` 中可以保存工程快照与合成测试结果，但不得把该目录整体映射到公网。签名私钥及其密码只进入受控私有保存位置。

## 下一阶段与验收顺序

### 1. 可在真实安卓设备使用的家庭试用版

0.2.0 已完成服务器上线、客户端预置地址和签名包交付，仍待家庭首次开通及实际手机/平板验收。

本会话负责客户端预置 HTTPS 地址、持续可更新的签名与版本管理、拍照和校对交互；“大小宝名校计划”负责移动端接口、后台任务和家长网页的部署准备；部署与数据迁移由后者统一执行，避免并行修改生产环境。

启用新版后台前，核对家庭登录、学生归属、配置和资源限制；停止写入并保留数据库与照片的一致性快照，候选实例验证后再切换。回退需要与旧代码匹配的数据快照，不能仅切换旧版本链接。新 APK 预置公开服务地址，避免用户手填；真实模型验收单独记录，不用模拟结果代替。

验收流程：家庭登录 → 新建或切换学生 → 拍一张含多题的照片 → 核对或调整题框 → 核对孩子手写过程 → 保存并重新打开 → 家长网页查看同一学生的数据。需要在实际手机或平板验证相机权限、相册、登录保持、断网重试及切换孩子后资料不串用。当前没有连接真机，实际设备检查仍待完成。

### 2. 用真实作业验证切题与手写识别

由家庭提供获准处理的约 20–30 张作业样本，覆盖同页多题、共用题干、分数和竖式、涂改、老师批注、模糊和倾斜照片。统计漏题/并题、框选偏差、关键符号转写错误、答题步骤遗漏与归属、人工修改耗时；保留样本原图和人工核对结果，依据结果选择或调整识别服务。

不确定项由人校对，原图始终可回看。单张静态照片只复现可见的书写内容与排布，不把推测的书写先后顺序当事实。习惯或知识薄弱点需要结合多次独立作答，以证据与待验证假设呈现。

### 3. 数学教学闭环

从少数年级知识点开始：基于已校对题目和原始作答定位第一处可观察错误 → 提供分步提示 → 孩子继续作答 → 给一道独立变式题 → 记录是否独立完成及用过的提示。家长可看到题目、原始过程、校对内容、辅导记录与待复习建议。

每个孩子单独积累结果。单次识别、一次错题或看过讲解后答对均不能直接判断长期掌握水平。整卷自动整理、多科目及更深入的思维训练在上述流程稳定后扩展。

## 开发与构建

客户端是独立 npm 项目，不修改服务器根 `package.json` 或锁文件。Node 24；Android 使用 Java 21、SDK 36 与项目 Gradle Wrapper。依赖由客户端 `package-lock.json` 固定。

```powershell
cd clients/android
npm ci --no-audit --no-fund
npm run dev
npm run build
npm run lint
npm test
npm run android:sync
cd android
.\gradlew.bat :app:assembleDebug
```

Vite 仅监听 `http://127.0.0.1:3178`。本机 Windows 排除端口包含 4178，故不用该端口。开发后端的 `FAMILY_MOBILE_ORIGINS` 需精确包含此来源和 Android 的 `https://localhost`，浏览器请求 `credentials: omit`；不要放宽网页 Cookie 路由的同源规则。

构建时可设置 `VITE_API_URL=https://自己的服务/family-learning/api/mobile/v1`，只放公开服务地址。未设置时，登录页提供初次服务地址配置。仅开发模式允许回环 HTTP；APK 和生产 Web 构建要求 HTTPS。不要在 APK 中使用 `server.url` 直接加载远程网页，也不要关闭证书验证。

手动执行 `assembleDebug` 生成 `android/app/build/outputs/apk/debug/app-debug.apk`，使用调试签名。家庭试用交付请执行上述 `scripts/build-pilot.ps1`，沿用长期发布签名，不能把签名私钥、密码、学习原件和测试账号提交 Git。

## 构建与检查

```sh
npm ci
npm test
npx tsc --noEmit
npm run build:self-hosted
```

构建使用当前锁定的 vinext 独立 Node 输出，生成 `dist/standalone`。
本地运行：将 `HOST=127.0.0.1`、`PORT=3190`、`NODE_ENV=production` 设置到运行环境，再执行 `npm run start:self-hosted`。
运行 `node scripts/smoke-self-hosted.mjs http://127.0.0.1:3190` 验证页面、练习、静态资源和受保护接口。
普通 `npm run build` 保留 Sites 构建方式。

`node scripts/verify-family.mjs` 会在两个浏览器和两个临时服务器中验证登录、断网补传、扫描与错题、备份导入、退出隔离、完整备份还原及原有学习流程。需要 Playwright / Edge；可用 `PLAYWRIGHT_MODULE_PATH` 指定现有运行时。测试目录位于忽略的 `work/`，截图位于 `outputs/`。默认不调用收费模型；仅在设置测试专用的 `FAMILY_TEST_AI=1` 与模型环境变量时，用合成题图片测试实际识题。

## 私有配置

两个私有环境配置文件保存在工程 `config/` 内（root:root，0600），由 `config/systemd/` 的完整服务配置加载；旧 `/etc/family-learning-*.env` 仅保留兼容链接。配置值不能进入仓库、构建产物或前端：

| 变量 | 用途 |
| --- | --- |
| `FAMILY_DATA_DIR` | `/home/ubuntu/codex_project/workspace_own/family-learning-hub/data`，原件和 SQLite 私有目录 |
| `FAMILY_BACKUP_DIR` | 工程的 `backups/daily/`，完整快照目录 |
| `FAMILY_PUBLIC_ORIGIN` | `https://123.207.232.151`，精确校验写请求来源 |
| `FAMILY_SETUP_TOKEN` | 随机 32 字节以上的首次启用码；仅首次创建账号使用 |
| `FAMILY_AI_API_KEY` | 服务器侧模型密钥 |
| `FAMILY_RECOGNITION_ENABLED` | 只有精确值 `true` 才启用识别；默认关闭。移动接口、网页和 worker 统一遵守，暂停队列不会消耗尝试次数或日额度 |
| `FAMILY_MOBILE_ORIGINS` | 生产安卓精确来源 `https://localhost`；不要加入开发端口或通配符 |
| `FAMILY_AI_BASE_URL` | DeepSeek 为 `https://api.deepseek.com` |
| `FAMILY_AI_MODEL` | `deepseek-flash`，支持图片输入 |
| `FAMILY_AI_PROTOCOL` | `chat-completions`；适配层也支持 `responses` |
| `FAMILY_AI_JSON_MODE` | DeepSeek 使用 `json_object` |
| `FAMILY_LEARNING_DAILY_LIMIT` | 每家庭24小时学习生成/批改任务额度，默认30，上限200；出题含第二次复核请求 |
| `FAMILY_AI_DAILY_LIMIT` | 每家庭每个 24 小时窗口最多识题次数，默认 10，上限 50 |

依据：[DeepSeek 图像输入](https://api-docs.deepseek.com/guides/vision/)、[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)。DeepSeek 当前不接收 PDF 文件输入，本版不会把 PDF 当图片请求发送；原 PDF 仍可上传、查看和手动整理。

密码采用 scrypt，数据库只保存会话令牌哈希；Cookie 为 HttpOnly / Secure / SameSite=Strict。首次只允许创建一个家庭账号。扫描最大 8 MB，总空间 500 MB，回收站文件仍计入空间；修改带版本号，避免两台设备覆盖彼此编辑。

## 服务器布局

工程总目录：`/home/ubuntu/codex_project/workspace_own/family-learning-hub/`。
完整的目录职责、权限和系统链接见 [工程目录](工程目录.md)。

- `code/`：源码、Git 和开发依赖；在这里运行 Git、npm 和测试命令。
- `runtime/releases/` 与 `runtime/current`：线上版本和当前版本链接。
- `data/`：真实学习数据与归档扫描原件。
- `backups/`：每日、发布前及迁移备份。
- `config/`：私有环境变量、systemd、Nginx 与日志轮转的实际配置。
- `temp/` 与 `artifacts/`：部署/媒体暂存、合成测试数据和测试产物。

系统服务入口和 Nginx include 位于原系统路径，均链接到本工程配置。Node 只监听 `127.0.0.1:3190`。共享 Node.js、Nginx、HTTPS 证书及续期服务留在公共环境。

继续开发时进入 `code/`，源码更新不会自动替换 `runtime/current`。Windows 本机保留恢复副本。

服务器已有其他网站。仅在既有 HTTPS server 块加入：

```nginx
include /etc/nginx/snippets/family-learning-location.conf;
```

配置模板在 `deploy/`。修改 Nginx 前备份，执行 `nginx -t` 成功后再 reload。
证书由服务器现有续期任务管理；本项目不另设证书和防火墙入口。

## 更新与回退

1. Git 拉取确认后的提交，在开发电脑构建并通过检查。
2. 将 `dist/standalone/` 打包，经 SSH 上传新版本目录。
3. 在备用回环端口启动候选版本，运行 smoke 脚本。
4. 将 `current` 指向已验证版本，重启 `family-learning-hub`。
5. 对公网 HTTPS 地址运行同一 smoke 脚本，并检查其他已有网站仍可访问。

若发布涉及移动扫描存储，失败时停止网页和 worker，保存上线后新增数据，再恢复发布前的数据库、原件及配置快照并将 `current` 指回旧版本。不能只切换代码：新版 SQLite 文档/版本为权威数据，旧 `record.json` 可能较旧。不要删除旧版本或覆盖其他网站配置；保留 APK 下载 include。
连接信息仅从私人服务器配置文档读取，密码、密钥和文档副本均不提交 Git。

应用日志在工程 `runtime/logs/`；迁移前的系统日志已导出到该目录。systemd 状态事件仍可通过 `journalctl` 查看。
服务状态：`sudo systemctl status family-learning-hub --no-pager`。

## 完整备份与恢复

安装 `deploy/family-learning-backup.service` 和 `.timer` 后启用定时器。每天北京时间 03:30 附近备份；首次部署也应立即执行一次。快照在工程 `backups/daily/family-<时间>/`，包括 SQLite、扫描原件、记录 JSON 和 SHA-256 清单，保留最近 30 份。原件不可变，元数据原子写入；在线快照可能略早于同一时刻的新上传，跨文件不构成单一事务。重要更新前短暂停止本应用并额外做完整归档，确保一致。

恢复前停止本应用并备份现状，在**新的目录**校验 `manifest.json` 所有文件哈希和 SQLite `PRAGMA integrity_check`。恢复数据库及哈希命名的原件目录，移除恢复目标中旧数据库的 `-wal` / `-shm`（不能对运行中的数据库操作）。恢复到工程的 `data/`，设置专用用户 `family-learning-app` 持有、目录权限 0700 后重启。配置文件单独安全备份，不从 Git 恢复。运行临时独立实例验证账号、同步记录与原件，再切换生产目录。当前没有永久删除扫描的用户入口。

依据：[vinext 独立部署说明](https://github.com/cloudflare/vinext#standalone-output)。

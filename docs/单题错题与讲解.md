# 框题、逐题选科、错题保存与 AI 讲解

2026年10月3日用户确认的纸面批改标记及重点题收录规则见 [错题与重点题目收录标准](错题与重点题目收录标准.md)。自动收录的产品判断以该标准为准；下文保留现有框题、保存和讲解接口说明，不表示自动规则已经上线。

用户操作顺序是拍照/选图 → 框出题目 → 为这道题选科目 → 保存为错题 → 显式点击 AI 讲解。上传只要求学生、出处和文件；没有科目时保存为 `待选择`。旧图片上的 `scan.subject=数学` 不代表用户已经确认题目科目。同一张图片的多道题可选不同学科。

每道 `Question.subject` 可省略，填写时必须属于 `数学、英语、地理、物理、化学、生物`。保存错题或提交单题 AI 前必须有题目科目以及有效 `stem` 题干框；不要求事先输入文字，AI 从框图提取题干。正式图片保持原位置与原字节；区域、题目、科目、收录和讲解都记录在 SQLite 文档及版本历史中。

## 移动接口

以下路径相对 `/family-learning/api/mobile/v1`。均需 Bearer 登录，沿用学生/家庭归属、精确来源限制和 no-store 规则。`scanId` 不能跨家庭访问。

| 方法与路径 | 请求 / 返回 |
| --- | --- |
| `PUT /scans/:scanId/review` | `{revision,questions}`；Question 可带 subject。返回 `{scan}` |
| `POST /scans/:scanId/questions/:questionId/wrong-book` | `{revision,saved:boolean}`；返回 `200 {scan}` |
| `GET /wrong-book?studentId=...` | `{items:[{scanId,studentId,subject,source,question}]}`，按收录时间倒序 |
| `POST /scans/:scanId/questions/:questionId/explain` | `{revision}`；返回 `202 {scan}`，此后轮询原有 `GET /scans/:scanId` |

修订号以最近一次返回值为准，过期返回 409，客户端保留草稿并刷新比较；不能连用旧 revision 发送“校对 → 收录 → 讲题”。重复设置相同收录状态不追加版本。每页同时只运行一个 AI 任务；相同已排队题目重试不创建第二个任务，其他题等待当前任务结束。

新字段由服务器管理，客户端在 review 中传回时只用于兼容完整对象，不作为写入依据：

```ts
wrongBook?: { savedAt: string };
tutoring?: {
  status: 'queued' | 'processing' | 'needs_review' | 'failed' | 'stale';
  result?: {
    transcribedPrompt: string;
    referenceAnswer: string;
    explanation: string;
    answerEvidence: { text: string; author: 'student'|'teacher'|'unknown' }[];
    errorHypotheses: { text: string; evidenceIndexes: number[] }[];
    uncertainties: string[];
    generatedAt: string;
    needsReview: true;
  };
  error?: string;
};
```

Review 忽略伪造的收录/AI 字段，保留服务器已有值。题干、科目、选框、作答步骤、共享区域或父题上下文改变时保留旧 result 并标 `stale`；进行中的任务会取消，晚到结果不能覆盖新草稿。重新显式讲解清掉当前旧 result，历史仍存 `scan_versions`。

## 原图处理与模型边界

后台使用显式固定依赖 sharp 0.35.2（原已为框架间接依赖），先处理 EXIF 方向，再按选定题和关联题干/配图的外接矩形裁切，在内存中缩放到最长 2400 像素后生成 JPEG。原图最大 3200 万像素，选框最小 8×8 像素；异常/多页图片拒绝，不覆盖原件。该流程只支持 JPEG、PNG、WebP 照片；PDF 原件可继续归档，但不进入这个按照片框选的讲解接口。裁切不产生散落临时文件。

模型只处理选定题，科目取 Question.subject。题干转写、参考解法和可见笔迹独立存储，不自动覆盖用户校对的 `prompt` 或 `answerSteps`。图中文字和人工上下文都作为不可信学习材料处理。条件缺失时说明待核对，不能编造标准答案；没有可见学生作答时不推断错因。每项错因假设须引用输出中学生笔迹证据，老师/不明作者笔迹不作学生错误依据；统一标明 AI 草稿待核对，不能推断性格、粗心、智力或能力，不自动打分、改变掌握度。

仅显式的 explain 请求排队。上传、框选、改科、收录、查看错题均不触发模型。单题与整页识别共用 `FAMILY_RECOGNITION_ENABLED` 和每家庭 24 小时额度，模型连接失败沿用有限重试。关闭开关不会消费排队任务或额度；失败不删除错题和原件。

## 存储与发布

`scan_jobs` 增加可空 `question_id`，启动时按列存在性做可重复的增量迁移；原有整页任务为 null。归档资料保留原路径 `data/<owner hash>/scans/<scanId>/original`，权威元数据仍在 `data/family.sqlite`。版本快照和原件必须一起备份，不能只恢复 `record.json`。

部署前按工程规则完成停写一致性快照、恢复到隔离目录、旧数据/原件校验及相同服务身份的 Web/worker 验证。standalone 必须实际携带 sharp 及当前平台原生依赖，并在服务器隔离候选上做真实裁切测试；不能只凭编译通过。

回退注意：旧 worker 不认识 question_id，会把此类任务误当整页识别。切旧 worker 前必须停止两个写入进程，取消 question_id 非空的 queued/processing 任务及租约，并把相应题目的活动状态标为已过期；保留数据库和原件，不能恢复旧快照覆盖新写入。旧 review 接口不保留新字段，因此出现问题优先关闭 AI 开关、保留本版读写能力并向前修复；不得让旧 review 继续编辑新格式的题目。旧运行版本只作为维护回退，恢复编辑前需要兼容修复版本。

新增合成测试覆盖无科上传/逐题选科、空文字框题、按题收录及家庭隔离、真实裁切/EXIF、服务器字段保护、修改后过期、晚到任务拒绝、模型失败/暂停/额度、旧库迁移及证据约束；测试不调用真实模型或读取生产原图。

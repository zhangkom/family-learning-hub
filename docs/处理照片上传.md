# 处理照片上传（本地待联调）

用户确认的默认流程是原片留在 APK 手机私有目录，上传用户预览确认的处理图。服务器不要求另传相机原片。正式上传字节仍固定存于工程 `data/<sha256(scanOwner)>/scans/<scanId>/original`；这里的 original 表示原始上传字节，对于 processed-photo 就是处理图，不能称为未处理相机原片。候选框及人工题框都针对这份上传处理图，历史图片坐标不迁移。

客户端上传前检查 `GET /api/mobile/v1/setup` 的 `processedPhotoMetadataVersion === 1`；缺少能力时停止本流程，避免旧服务器忽略元数据后产生错误档案。保存回执、扫描列表和详情中的 `scan.sourceKind/scan.processing` 供客户端复核实际持久化内容。

multipart POST scans 新增：

- `sourceKind=processed-photo`。
- `processing` 是 `PreparedPhoto` 去掉 `uri` 后的 JSON，类型见 `lib/photo-processing.ts`；不能上传 owner、任何 URI、本地路径或其他未知字段。
- `clientRequestId` 必须等于 `processing.outputId`（UUID，比较转小写），每个处理版本固定标识。同一标识重试只有文件、学生及完整规范化元数据一致才返回原 scan；异内容返回 409/IDEMPOTENCY_CONFLICT。
- `studentId` 必须属于当前家庭，且与 processing.studentId 一致。服务端不信任客户端 owner。

服务器核验输出 SHA-256、字节数、JPEG MIME、实际像素尺寸、无待应用 EXIF 方向、单张图及完整解码。限制上传 8 MiB、边长 16–4096 且不超过 maxEdge，输出约 800 万像素上限（容纳 native 四舍五入）；元数据 JSON 16 KiB。来源声明限 1 亿像素/边长 50000、解码约 1200 万像素/边长 8194，并核对 EXIF 方向与解码比例。参数与 android-photo-v1 对齐：maxEdge 256–4096，JPEG 质量 90–100，quarterTurns 0–3，增强 none/light。

四角限定为 EXIF upright 的归一化顺时针凸四边形，面积及边长不能过小。两套矩阵必须有限、有界、可逆，四角映射与旋转匹配，反变换及内部点往返一致；输出尺寸需符合 native 的裁切/缩放公式（1 像素容差）。处理空间固定 `sourceSpace=exif-upright-normalized-edges`、`outputSpace=normalized-edges`。服务端没有相机原片，`sourceSha256`、原片尺寸/EXIF、质量指标和处理参数仍是经过一致性校验的客户端声明，不能宣称已验证原片内容、图像来源或增强实际执行效果。质量预警仅供用户复核，不用于自动评价学习能力。

无 sourceKind/processing 的历史客户端上传继续走原流程，fingerprint 算法不变，不重新标记旧资料。处理信息存入已有扫描 JSON 与修订记录，无数据库迁移；校对/讲解不覆盖此信息，备份沿用原件+record.json+SQLite。回退不删除新资料；旧版服务能力接口不声明本功能，客户端必须停止 processed-photo 新上传。禁止把处理图重新解释成相机原片来绕过兼容检查。

本地测试涵盖 8 种 EXIF × 4 次旋转、裁切及映射、字节/尺寸/编码不符、截断图、URI/未知/重复字段、非法矩阵、家庭隔离、处理版本去重、同标识异内容拒绝、回执/校对保持和历史上传兼容。仅使用合成 JPEG，零 AI 调用。实际安卓宿主接入、设备试拍与生产发布另行验收。

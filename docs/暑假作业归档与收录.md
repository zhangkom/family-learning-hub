# 暑假作业归档与收录

更新日期：2026-10-03。本文说明本次实现的逻辑归档、纸面标记收录和主机导入协议。代码通过测试不等于已部署、已完成真实资料导入或已通过手机验收；交付记录应分别说明这些结果。

本次正式部署、200张真实资料导入及客户端验收结果已分别记录于 [0.3.12交付与整体验证](android-0.3.12-release.md)。该记录包含逐模块流程、异常复测、待补资料和真机验证边界。

## 资料与题目的关系

资料按家庭、学生、科目和实际卷面作业标题归档。图片云盘展示“科目 → 作业 → 原页”，未分类照片在“待整理”中。分类只修改数据库关联，原照片的位置、字节、原文件名和原有上传回执保持不变。混合批次不能直接当作同科同卷。

每份作业有独立 `documentId`。`pageNumber` 是资料内唯一显示顺序；`paperPageNumber`、`paperPageCount` 是实际印刷的页码与页数；`pageRole` 区分题卷和答题卡。两种页码不能混用，例如资料内第九张照片可以是答题卡第1页。无法确认的印刷页码不填写。原页可用 `duplicateOfPhotoId` 标记重复拍摄，原件仍保留；重复页只能归档，不再收题。近似照片的重复关系由人工核对，不按相同文件名或自动猜测建立。

题目和扫描保存 `sourcePage`，记录原页、作业、科目、资料页序、物理页码、题号、小问及校验值。已有扫描通过明确的 `existingScanId` 与现存扫描文件 SHA-256 关联，不以同名代替身份核对。

## 单题与跨页图片

单页题可以引用摆正后的处理图及归一化题框。`rotationClockwise` 为 EXIF 摆正后再顺时针旋转的角度，只接受 0、90、180、270。坐标对应处理后的正向图片，不能把未旋转图片的坐标套到旋转副本上。原云盘照片始终保留，处理图另存稳定扫描位置。

跨页题由人工核对的 `sourceParts` 组成，每片保存来源照片、原件 SHA-256、旋转、裁框与用途：`material`、`question`、`answer` 或 `figure`。服务端实际从这些原页裁取像素，按清单顺序纵向拼接，以便现有客户端直接显示完整题图。返回 `composedRect` 标出每片在组合图内的位置，并补充可查到的作业标题、印刷页码与原文件名。

组合必须包含主来源页，最多16片；每片宽度最多2000像素且不放大，片间留16像素白边，输出 JPEG。必须保留解题需要的共同材料、完整题干、选项、图表和批改证据。答题卡中的答案框不能代替其他页上的完整题目。组合图不是重新排版、去除手写或独立印刷题库；与邻题重叠的原手写可能仍需要人工调整分片。

原件及处理图须在32 MiB、3200万像素以内，处理图仅支持单帧 JPEG、PNG、WebP；组合高度也受 JPEG 格式限制。单次导入累计处理图最多256 MiB，超过时拆成多个清单，不降低完整性强行收录。原件缺失、哈希不符或图片不可解码时停止该清单，不生成无法在手机恢复的记录。

客户端读取题图仍遵守本机优先：已存在的本机题图直接使用；显示题目时缺失或损坏才自动从受保护的扫描文件接口恢复，失败后显示手动重试。组合处理图不是另一次原件云盘上传，也不会把原件移入公開下载目录。

## 纸面标记与学习记录

收录依据遵循 [错题与重点题目收录标准](错题与重点题目收录标准.md)。每题 `paperMark` 包含 `classification`、规则编号、可核对的证据文字及可选证据区域，另由服务端写入复核时间、`reviewedBy: codex-manual` 和 `independentAssessment: false`。

| 分类      | 规则校验                     | 保存结果                         |
| --------- | ---------------------------- | -------------------------------- |
| `wrong`   | 至少一个 R01–R04             | 加入错题本                       |
| `focus`   | 至少一个 R06、R07            | 加入重点题，不新增错题属性       |
| `both`    | 错题规则、重点规则及 R08     | 同一题同时具备两个属性           |
| `pending` | 包含 R09，未确认且有具体疑点 | 保留待核对，不新增错题或重点收藏 |

`wrongBook.savedAt` 与 `focusBook.savedAt` 分开保存，重复核对不会重置既有收藏时间。已有收藏改为 `pending` 会返回冲突并保留原记录，须先核对收藏与疑点，不能用导入过程悄悄撤销确认。旧版客户端编辑题目时遗漏新字段，不会抹去服务端的来源、纸面标记和重点属性。

原答案、订正及批改关系须如实记录；看不清的原答保留疑点，不补造学生答案。收录不创建独立练习、复测或能力得分。知识点标签仅描述题目涉及内容，不是成绩，也不是已完成多题薄弱点分析的证明。来源关联或纸面标记更新本身保留已核对的旧讲解；题干、学科、共享条件、题框、作答、确认或参考答案等实际内容改变后，相关旧讲解标为过期并保留历史内容。清单不能携带伪造的 `tutoring` 或复核结果。

## 查询接口

接口均位于受登录保护的 `/family-learning/api/mobile/v1/` 下，家庭身份来自会话，学生归属须存在。

| 请求                                                             | 返回内容                       |
| ---------------------------------------------------------------- | ------------------------------ |
| `GET cloud-photo-folders?studentId=…`                            | 各科资料数、照片数、待整理数   |
| `GET cloud-photo-folders?studentId=…&subject=…&limit=…&cursor=…` | 该科资料列表及下一页游标       |
| `GET cloud-photos?studentId=…&documentId=…&limit=…&cursor=…`     | 按资料页序排列的原页及归档信息 |
| `GET cloud-photos?studentId=…&unclassified=1&limit=…&cursor=…`   | 仅未分类照片                   |

资料与照片列表支持1至100条分页；这不是上传或选图数量上限。游标限定于对应家庭、学生和查询范围。`setup.cloudPhotos.archiveVersion = 1` 表示支持上述浏览能力；旧客户端仍可使用普通云盘列表，新客户端对未声明能力的旧服务保留兼容路径。查询不暴露其他家庭资料。

## 主机导入协议

写入入口是 `server/homework-cli.ts`，构建产物为 `dist/standalone/tools/homework-import.mjs`。没有公开 HTTP 分类写入接口。通过标准输入传入私有 JSON，避免资料进入命令行参数；不加参数默认完整验证并回滚，只允许 `--apply` 写入。标准输入最大32 MiB。

顶层字段：`version: 1`、新的 UUID `requestId`、现有管理员账号标识 `actorAdminId`、目标 `accountId`、`studentId`、`visualReview: codex-manual`、`pages`。管理员资格按数据库账号标识检查，不能以用户名推断权限。一次最多5000条资料页记录；实际收题仍受处理图累计容量限制。

每条页记录要求 `photoId`、`sha256`、`documentId`、`title`、`subject`、唯一 `pageNumber`、`expectedArchiveRevision` 和分卷依据 `classificationEvidence`。可补物理页码、页类型、重复拍摄关系和旋转。

- 只分类时省略 `questions`，不会创建新扫描或运行模型。
- 收题时提供符合 `validateQuestions` 的 `questions`、每题 `paperMark` 和 `expectedScanRevision`；每页最多100题。题号中的大题和小问可额外写入题目的 `sourcePage.majorNumber/subNumber`。
- 新扫描 ID 根据家庭和原页稳定生成；同一主来源页需要多个独立组合图时显式提供稳定 UUID `scanKey`。同一逻辑题重试必须沿用题目 ID 与 `scanKey`，随机换 ID 不能实现去重。
- 复用已有扫描时提供 `existingScanId`、`existingScanSha256` 和预期扫描版本；不能用新的 `sourceParts` 覆盖旧扫描原件。
- 同一清单不重复列主来源照片。分类阶段完成后，逐份作业或逐个组合图提交后续清单，使用当前资料版本与扫描版本。

同一个 `requestId` 与完全相同清单重试，返回既有回执；同一标识携带不同内容返回409。其他设备修改、原件被替换、资料页序占用、作业身份冲突、扫描正在处理或处理图哈希改变也会拒绝。不能绕过冲突套用旧坐标。`dry-run` 同样检查已有扫描文件冲突。

元数据、扫描记录、版本快照、导入回执和管理员审计在同一 SQLite 事务提交。审计记录操作者、目标归属、请求及原页标识，题目历史保留在 `scan_versions`。写文件使用独立扫描目录及排他创建，永不覆盖已有不同字节；文件系统写入不具有数据库事务原子性，磁盘故障可能留下未被数据库引用的处理文件。重试核验相同哈希后复用，不能为了清理而删除云盘原件。生产操作前仍需正式备份，并先在恢复副本验证同一清单。

## 已测范围与后续边界

`server/homework.test.ts` 使用合成图片和独立临时数据库验证：资料页与答题卡物理页码分离；只验证不落库；幂等重试；账户/学生隔离；分类版本冲突；资料内页序重排；规则与待确认校验；错题/重点双属性；原件和收藏时间保留；旋转副本与坐标版本保护；跨页像素组合与溯源；重复拍摄不重复收题；待确认更新冲突；已有文件冲突；缺失原件；文件和组合像素上限；同批次来源页信息；纯元数据更新保留已核对讲解；父题变化使关联子题讲解过期；拒绝伪造讲解复核。

这些测试不调用真实模型，不代表全自动纸面识别已上线，也不能替代全部真实题图的人工完整性复核或真机测试。发布前应结合客户端浏览、题卡配图、自动恢复、筛选及来源跳转回归；真实导入后核对总数、待确认数、归属、来源哈希、题图恢复和旧记录保留。尚未完整拍摄的续页仍须标记待确认；自动卷面分类、自动跨页关联、去手写打印排版及独立解题审核不由本导入工具自动完成。

真实原图、清单、裁框检查图、用户标识和授权资料只保留于私有资料及忽略目录，不进入本文、Git、公开 APK 或公开验证截图。

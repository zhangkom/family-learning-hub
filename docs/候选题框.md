# 候选题框接口

2026-10-01 已部署后台 `887ee6c4148b6e5e9dd7de7c76bcede66b459ab5`，APK 0.2.8/code10 源码为 `a7b5711bf853703410cf70b138f5d2ed3a6a5ee1`。两者提交分别记录，详见 [0.2.8 发布记录](028发布记录.md)。

`POST /family-learning/api/mobile/v1/scans/:id/candidate-regions`，JSON 请求 `{ "revision": 0 }`。沿用 Bearer、家庭/学生归属和 CORS 校验；成功直接返回 `lib/mobile.ts` 中的 `CandidateRegions`，无 scan 包装。请求前后都检查资料版本，过期返回 409。接口不保存候选，不改题目、科目、版本，不调用 AI；限流计数及旧扫描的兼容导入仍可能写数据库。

坐标为 EXIF 纠正后的图像归一化坐标。`image.width/height` 是纠正方向后的完整图片尺寸，不是计算时缩小的尺寸。客户端需核对 scanId、revision 和显示图片尺寸；候选先全不选，经人工选择、调整、拆并、核对图示和笔迹后，再通过已有 review 保存。`manual_required` 的 candidates 为空。

实现仅依赖已有 sharp，按连通域、栏间空隙及行间留白提出几何候选，没有 OCR、题号识别或语义保证。单题内部大留白可能被误切成多题；合成反例 `one-question-separated-paragraphs` 有 2 道人工定义题而输出 3 框。图示、手写批注、倾斜/透视、阴影和复杂排版都需要人工复核，不能宣传自动准确切题或准确率。

每个 Web 进程最多 1 个独立 Node 子进程，零等待队列，繁忙立即 503；每家庭每分钟 6 次。8 秒超时/取消终止子进程，容量到 close 才释放。程序源码固定打包为 raw 文本，图片通过标准输入传递；不经过 shell，不继承模型密钥。限制 JPEG/PNG/WebP、8 MiB、3200 万原始像素，分析图最多 200 万像素、宽 1200；最多 24 框。V8 堆 96 MiB 不等于总内存上限（sharp 原生解码另占内存）。PDF/坏图 400，尺寸超限 413，家庭限流 429，忙碌/未知尺寸超时 503；已得尺寸的超时返回 manual_required + PROCESSING_TIMEOUT。未添加运行依赖、数据库迁移和模型请求。
